## 아하 모먼트 (독자가 챕터를 닫으며 얻는 한 문장)

모델의 눈에 '딸기'는 글자들이 아니라 조각 몇 개다 — 지금 맞히는 것은 글자가 보여서가 아니라, 조각의 철자를 학습으로 외웠기 때문이다.

- 실측 주: o200k_base 기준 '딸기'는 3토큰(바이트 조각 2 + '기'). 본문 수치·예시는 위젯 실측값만 쓴다.

## 위젯

- **id**: `w-tokenizer` / **데이터 계층**: L1 (gpt-tokenizer 브라우저 실시간) / **구현 완료** (골든 10문장 + 바이트 폴백 + 무손실 분해)
- **핵심 조작**: 문장 입력 → 색 블록 분해 → 블록 탭(ID·바이트) → 한↔영 비교 → 인코딩 전환
- **조작 가이드 3개**:
  1. "안녕하세요"와 "hello"를 넣고 토큰 수를 비교해 보세요
  2. 자기 이름을 넣어보세요
  3. "딸기"를 넣고 몇 조각인지 보세요
- 사전 데이터 용량: §3.5 예외 조항 적용(재성 승인 2026-08-06) — 지연 로딩 + 용량 고지

## 본문 흐름 (위젯 목격 → 설명 → 훅 회수)

1. 파트 1 문지방 문장 + 'LLM' 어휘 다리(§11.3) + 훅 구체화: 2024년 밈 이야기 → "지금은 맞힌다"(재성 캡처) → "그럼 해결된 걸까?"라는 질문으로 위젯 초대 (2~3문단)
2. 위젯: 아무 문장이나 넣어 쪼개보기
3. 조작 가이드 3개 (위젯 바로 아래)
4. 설명: 토큰 = 서브워드 조각, BPE의 직관(자주 붙어 나오는 조각 병합 — sennrich2016), 글자·단어·토큰의 차이. '딸기'가 바이트 조각으로 쪼개지는 위젯 실례 회수
5. 한국어의 비용: 같은 뜻이라도 한국어가 토큰을 더 쓴다 → API 요금·컨텍스트 소모 직결 (petrov2023 — 수치는 원문 확인 범위에서만)
6. 훅 회수: 토큰 ID의 세계에는 'ㄹ'도 'r'도 존재하지 않는다. 그런데도 맞히는 이유 — 모델은 토큰의 철자를 학습으로 외운다. 그러나 그 지식을 다루는 데는 여전히 서툴다(edman2024 — CUTE). "맞힌다"와 "보인다"는 다르다
