## 아하 모먼트 (독자가 챕터를 닫으며 얻는 한 문장)

의미란 좌표다. 비슷한 뜻 = 가까운 위치 — 모델이 배우는 것은 결국 이 지도다.

## 위젯

- **id**: `w-embedding-map` / **데이터 계층**: L2 (사전계산 2D 좌표 + 유추 결과 재생)
- **핵심 조작**: 캔버스 산점도(단어 500~1,000개, 줌·팬) → 검색(단어 하이라이트 + 최근접 이웃 k=10 강조) → 유추 버튼 3~5개(사전계산 결과만 재생)
- **조작 가이드 3개** (§6 명세 그대로):
  1. '서울'을 검색하고 이웃을 보세요
  2. 감정 단어들이 모인 대륙을 찾아보세요
  3. "왕 − 남자 + 여자" 버튼을 눌러보세요
- **정직성 장치** (§8.2.3):
  - 고정 캡션: "이 지도는 300차원을 2차원으로 눌러 담은 그림자입니다"
  - 이웃·유추는 **원 300차원 공간 기준 계산**임을 명시(2D 좌표 연산 아님)
  - 데이터 캡션: FastText cc.ko.300 · 생성 메타(_meta) 노출

## 데이터 (`scripts/precompute/embedding_map.py`)

- 소스: FastText `cc.ko.300.vec.gz` (fasttext.cc 배포, CC-BY-SA 3.0) — 스트림
  파싱으로 상위 빈도 어휘만 읽음(전체 로딩 없음)
- 어휘 큐레이션 (~800개, **재성 확정 대상**): 카테고리 시드(지리·가족·감정·
  음식·동물·직업·시간·색·학문 등) + 빈도 상위 한글 단어 보충. 시드 목록은
  스크립트 상단 상수
- 유추 후보 5개 (실행 결과 품질로 채택 — D3 최종 확정 기준):
  왕−남자+여자 / 서울−한국+일본 / 아빠−남자+여자 / 형−남자+여자 /
  파리−프랑스+한국
- 산출: 2D 좌표(UMAP, 시드 고정) + 단어별 원 공간 이웃 k=10 + 유추 결과
  top-3 — JSON 300KB 예산 내 (§3.5)

## 본문 흐름 (§6 준수)

1. 훅: 단어 산수 — 믿기 어려운 주장으로 시작 (1-2의 nextHook "숫자에 불과한
   토큰이 어떻게 의미를 갖게 될까요?"를 받음)
2. 위젯: 한국어 단어 지도 탐색
3. 조작 가이드 3개
4. 설명: 원-핫의 한계(모든 단어가 서로 남) → 밀집 벡터, 거리 = 유사도,
   이 지도가 학습으로 만들어진다는 예고(3부 복선)
5. 정직한 각주: 2D는 수백 차원의 그림자 — 지도에서 가깝다고 무조건 원
   공간에서 가까운 것은 아님
6. 훅 회수: 유추 버튼 — 의미의 방향(성별·수도 관계)이 벡터 연산으로 드러남
