## 1. 디자인 방향

### 1.1 콘셉트 — "설계도와 도장 (Blueprint & Seal)"

이 사이트가 하는 일은 LLM이라는 기계의 **내부 설계도를 펼쳐 보여주는 것**이다. 비주얼 아이덴티티를 그 세계에서 가져온다.

- **도면지**: 라이트 모드는 차가운 종이 위의 잉크. 위젯 영역은 은은한 모눈(방안지) 시트 — "여기는 작동하는 도면"이라는 신호.
- **청사진**: 다크 모드는 문자 그대로 청사진(blueprint) — 깊은 남색 바탕 위의 밝은 선. 라이트↔다크가 "도면지↔청사진"이라는 하나의 이야기로 묶인다.
- **쪽빛(인디고)**: 구조를 담당하는 단일 기간(基幹) 색. 링크·포커스·다이어그램·파트 표기가 전부 쪽빛의 농도로 통일된다.
- **인주(印朱) 도장**: 이 사이트의 시그니처. 완독 스탬프와 검증 배지에만 쓰이는 주홍색 도장 모티프. **도장은 아껴 찍는 것** — 희소해야 신뢰의 표식이 된다.

무드 한 줄: *정밀한 공학 문서의 신뢰 + 한국적 검증 표식.* 화려함이 아니라 정확함이 아름다움인 디자인.

### 1.2 시그니처 요소 (단 하나)

**인주 도장 시스템.** 챕터 완독 시 커리큘럼 맵의 챕터 카드에 주홍 원형 스탬프가 '찍히고'(–5° 미세 회전, 220ms 스케일 다운 모션 1회), 검증 배지(`lastVerified`)에도 소형 도장 아이콘이 붙는다. 나머지 모든 요소는 조용하게 유지한다 — 대담함은 여기 한 곳에만 쓴다. (스탬프 내부 글리프 — 체크 vs "완" vs 문양 — 은 재성 결정 대기, §11)

### 1.3 하지 말 것 (금지 목록)

신뢰 톤을 지키기 위한 명시적 금지. 구현 중 아래가 나타나면 즉시 되돌린다.

1. **AI 디자인 클리셰 3종 금지**: ① 따뜻한 크림 배경(#F4F1EA류) + 세리프 + 테라코타 포인트 조합 ② 검정 배경 + 형광 그린/버밀리언 단일 포인트 ③ 헤어라인 가득한 신문 조판 흉내. (우리의 종이색은 **차가운** 회백, 주홍은 **도장 전용**이라는 점이 ①과의 결정적 차이 — 이 구분을 무너뜨리지 말 것)
2. 그라데이션·글로우·글래스모피즘·과한 그림자 금지 (그림자는 팝오버 1단계만 허용)
3. 이모지 금지 (KICKOFF §9의 보류 사항 확정: **미사용**. Depth 라벨 등은 텍스트+선 아이콘)
4. 보라-파랑 그라데이션, "AI스러운" 뉴런/회로 스톡 일러스트 금지
5. 8px 초과 라운드를 카드 외 요소에 사용 금지 (공학적 정밀함 유지)
6. 인주색을 도장·검증 표식 외 용도(버튼, 링크, 일반 강조)에 사용 금지
7. 장식 목적의 모션 금지 — 모든 모션은 "무엇을 가르치는가/무슨 상태 변화인가"에 답해야 함

## 2. 디자인 토큰

전 토큰은 CSS 변수로 정의하고 Tailwind 설정이 이를 참조한다(`src/styles/tokens.css`). **컴포넌트에서 hex 직접 사용 금지** — 린트로 검사(§11).

### 2.3 콘텐츠 시맨틱 팔레트 (교육용 — 사이트 전체에서 의미 고정)

색이 곧 정보다. 아래 매핑은 챕터·위젯·다이어그램 어디서든 동일하게 유지한다(색 = 복습 장치).

```css
:root {
  /* 토큰(text token) 블록 — 순환 6색. 인접 블록 동일색 금지 */
  --tk-1-bg: #DCE7F3; --tk-1-fg: #27436F;
  --tk-2-bg: #DFEDE4; --tk-2-fg: #2F6D53;
  --tk-3-bg: #F4E9D7; --tk-3-fg: #7C5518;
  --tk-4-bg: #EDE1EC; --tk-4-fg: #6E3A62;
  --tk-5-bg: #DCEDEA; --tk-5-fg: #275F56;
  --tk-6-bg: #EFE2DB; --tk-6-fg: #7D4A2F;
  /* 다크 모드 값은 동일 색상(hue) 유지, 명도만 반전해 별도 정의 */

  /* 어텐션 세기 — 단일 색상 + 이중 인코딩(투명도 & 굵기) */
  --attn-hue: var(--jjok-600);
  /* 세기 0→1: opacity 0.15→1.0, stroke-width 1→4px. 색상만으로 구분 금지 */

  /* 파트 난이도 = 쪽빛의 깊이 (깊어질수록 심화 — 구조가 정보) */
  --part-intro:    var(--jjok-400);  /* 파트 1–2 입문 */
  --part-mid:      var(--jjok-600);  /* 파트 3–4 중급 */
  --part-advanced: var(--jjok-800);  /* 파트 5–6 심화 */

  /* 확률/수치 막대 기본 */
  --bar-fill: var(--jjok-500);
  --bar-track: var(--bg-inset);
}
```

## 3. 타이포그래피 상세

읽기 리듬이 이 사이트의 기본기다. 독자가 가장 오래 하는 행동은 '한국어 장문 읽기'이며, 아래 규격이 완독률을 좌우한다.

### 3.1 서체 역할 분담

| 역할 | 서체 | 사용처 | 이유 |
|---|---|---|---|
| 디스플레이 | **마루 부리** (MaruBuri) | 챕터 제목, 훅 인용, 아하 모먼트 콜아웃, 파트명 | 네이버가 화면 장문 읽기를 위해 설계한 부리(세리프) 계열. '출판물의 신뢰'를 화면 문법으로 구현. 위계 장식에만 절제 사용 |
| 본문·UI | **Pretendard Variable** | 본문, 제목 h2/h3, 버튼, 라벨 전부 | 한글 화면 가독의 실질 표준. 개성은 마루 부리와 레이아웃이 담당 |
| 코드·수치 | JetBrains Mono + D2Coding 폴백 | 코드, 토큰 ID, 계산기 수치 | 숫자 판독성. D2Coding은 한글 주석 폴백 |

**[재성 확인 액션]** 마루 부리 웹폰트 서브셋 배포 조건(네이버 글꼴 라이선스) 확인. 문제 시 폴백: Noto Serif KR — 단, 이 경우 클리셰 회피를 위해 사용 범위를 챕터 제목·훅 2곳으로 더 좁힌다.

### 3.2 로딩 전략

- 두 서체 모두 **한글 서브셋**(KS X 1001 완성형 + 자주 쓰는 확장) woff2, `font-display: swap`, 프리로드는 본문(Pretendard)만.
- 마루 부리는 제목 요소에만 적용되므로 지연 로딩 허용(FOUT 시 Pretendard 굵은 웨이트로 폴백해 레이아웃 시프트 최소화 — `size-adjust` 튜닝).
- 수식(KaTeX) CSS는 전역 로딩하되, 폰트 파일은 브라우저가 수식 렌더 시점에만 받는다(자연 지연 — @font-face 동작). 본문 인라인 수식 허용(§4.9)과 정합. *(v1.2.1 정정 — 기존 "dev 레이어 열림 시점 로딩" 문구 대체)*

### 3.3 본문 조판 규격

- 본문 폭 `--measure`(42rem), 좌우 패딩 모바일 20px.
- 문단 간격 `1.25em`, 제목 위 여백 `--sp-16`/아래 `--sp-4` (h2 기준), 위젯 시트 상하 여백 `--sp-12`.
- 굵은 강조는 문단당 최대 1회. 밑줄은 링크 전용. 형광펜식 하이라이트 금지.
- 링크: `--jjok-600` + 밑줄(두께 1px, offset 3px). 방문 색 구분 없음. 외부 링크는 ↗ 표기.
- 인용·훅: 마루 부리, `--text-hook`, `--ink-900`, 좌측 2px `--jjok-400` 룰.
- 숫자·단위: 본문 내 수치는 `font-variant-numeric: tabular-nums` (표·계산기에서 정렬 보장).

## 4. 컴포넌트 규격

MDX 컴포넌트(KICKOFF §4.2)의 시각 규격. 전부 `/styleguide`(§9)에 등재한다.

### 4.1 Term (용어 팝오버)

- 본문 내 표시: 점선 밑줄(1px dotted `--ink-400`) — 링크(실선·쪽빛)와 명확히 구분.
- 탭/호버 시 팝오버: `--bg-sheet`, `--r-card`, `--shadow-pop`, 최대 폭 280px. 내용 = 용어명(600) + oneLiner + "자세히 →" 링크. 모바일은 하단 시트 아님 — 같은 팝오버를 터치 위치 근처에.
- 키보드: 포커스 + Enter로 열림, Esc 닫힘.

### 4.2 Depth 카드 (깊이 토글)

존재감 밸런스가 이 사이트 고유의 난제(P1 흐름을 끊지 않되 P2·P3이 발견해야 함). 규격:

- 접힘 상태: 본문 폭 카드, `--bg-page`보다 반 톤(`--bg-inset`) 배경, 1px `--hairline`, 좌측 3px 수직 룰로 레벨 구분 — dev = `--jjok-500`, research = `--ink-400`.
- 라벨(15px, 600): `개발자 레이어 — 수식과 코드` / `연구 레이어 — 원문과 논쟁` + 우측 셰브론. 아이콘·이모지 없음.
- 열림: `--dur-ui` 높이 전환, 내부는 본문과 동일 조판. 열림 상태는 URL 해시(`#dev-1`)로 공유 가능, 해시 진입 시 자동 열림+스크롤.
- 첫 챕터(1-1)에 한해 dev 카드 아래 한 줄 안내: "이 카드는 더 깊이 보고 싶을 때만 열면 됩니다" — 이후 챕터에서는 반복하지 않음.

### 4.3 CheckQuestion (확인 질문)

- 시트 카드(`--bg-sheet`, `--r-card`), 상단 라벨 "확인 질문"(caption, `--ink-600`).
- 질문(본문 크기) + "답 보기" 버튼(고스트 스타일). 채점·입력 없음 — 탭하면 답이 `--dur-ui`로 펼쳐짐. 부담 최소화가 목적.

### 4.4 Refs (참고문헌) — 신뢰 UI의 핵심 1

- 논문 참고문헌 조판: 15px, hanging indent 1.25rem, 줄간 1.6.
- 각 항목 앞 등급 칩: `S1 논문`(쪽빛 100 배경/700 텍스트) / `S2 공식 문서`(inset 배경/ink-600). 칩이 출처 위계를 시각화한다.
- 섹션 제목 "참고문헌"(h3) + 상단 헤어라인. 숨기지 않는다 — 이 섹션의 존재 자체가 차별화.

### 4.5 검증 배지 — 신뢰 UI의 핵심 2 (시그니처 연동)

- 위치: Refs 아래 고정. 형태: 소형 인주 도장 아이콘(14px, `--inju-500`) + "원리 검증 2026-07-07 · 수치 데이터 검증 2026-07-01"(caption, `--ink-600`).
- 90일 초과 시 도장이 회색으로 바래고 "재검증 예정" 문구 — 신선도를 정직하게 노출하는 것이 신뢰.
- 탭 시 팝오버로 검증 프로세스 요약(5게이트 한 줄 설명 + 오류 제보 링크).

### 4.6 NextHook 카드

- 챕터 마지막 요소. 시트 카드 전체가 탭 영역.
- 구성: caption "다음 챕터" + 다음 챕터의 훅 질문(마루 부리, `--text-hook`) + 챕터 번호·제목(15px) + →.
- 호버: 배경 `--jjok-100` 전환(`--dur-micro`). 훅 질문이 카드의 주인공 — 궁금증이 클릭을 만든다.

### 4.7 FactValue

- 인라인 수치에 미세한 점선 하단 표시 + 탭 시 툴팁: "검증일 YYYY-MM-DD · 출처명". 본문 흐름을 해치지 않는 최소 장치.

### 4.8 진행 UI

- 챕터 상단: 파트 라벨(`파트 2 · 구조` — 해당 파트 쪽빛 농도) + 파트 내 위치 점(●●○○○).
- 커리큘럼 맵 챕터 카드: 훅 질문이 카드 문구(마루 부리 17px). 완독 시 우상단에 인주 스탬프(§1.2 모션).
- 진행률 텍스트는 "3/24 챕터"처럼 담백하게 — 게이지·퍼센트 링 금지(게임화는 나중 단계).

### 4.9 코드 블록·수식

- 코드: Shiki 테마를 토큰 기반 커스텀(라이트=도면지 위 잉크, 다크=청사진). `--bg-inset` 배경, `--r-card`, 언어 라벨 caption. 줄번호는 8줄 초과 시만.
- 수식: display 수식은 원칙적으로 Depth(dev) 내부에만(KICKOFF §9 유지). 본문 인라인 수식은 허용.

### 4.10 버튼·입력 기본형

- Primary: `--jjok-600` 배경/white 텍스트, `--r-ctl`, 높이 40px(터치 44px 확보는 패딩으로). Hover 700.
- Ghost: 투명 배경 + `--hairline-strong` 테두리. 위젯 내 보조 동작용.
- 입력·슬라이더: 트랙 `--bar-track`, 채움 `--jjok-500`, 썸 20px(터치 영역 44px). 슬라이더 값은 항상 인접 수치 라벨과 동기 표시.

## 5. 위젯 시각 언어

위젯은 이 사이트의 존재 이유다. "만질 수 있음"이 3초 안에 전달돼야 한다.

### 5.1 도면 시트 프레임 (모든 위젯 공통 셸)

```
┌─[직접 해보기]──────────────── ⛶ ─┐   ← 라벨 탭 + 전체화면(선택)
│ · · · · · · · · · · · · · · · · │   ← 모눈: 16px 격자, --grid-line
│        (위젯 콘텐츠)              │
│ · · · · · · · · · · · · · · · · │
├──────────────────────────────────┤
│ 데이터: kogpt2-base · 2026-06 생성 │   ← 출처 캡션 (L2 필수)
└──────────────────────────────────┘
```

- 폭: 본문(42rem)보다 넓은 **브레이크아웃 54rem**(뷰포트 초과 시 100%−40px). 본문 컬럼을 벗어나는 것 자체가 "구간 전환" 신호.
- 배경 `--bg-sheet` + 모눈 패턴(16px 라인 격자, `--grid-line`). 모눈은 위젯 셸에서만 — 페이지 배경에 쓰면 신호가 죽는다.
- 좌상단 라벨 탭: "직접 해보기"(caption 600, `--jjok-700`, `--jjok-100` 배경, 상단 모서리만 라운드). 사이트 전체에서 이 라벨 = 조작 가능 구간이라는 학습된 신호.
- 테두리 1px `--hairline-strong`, `--r-sheet`. 그림자 없음.
- 하단 캡션 바: L2 위젯은 데이터 생성 메타 필수, L1은 "이 계산은 브라우저에서 실시간으로 수행됩니다".

### 5.2 조작 가이드 칩 ("해보기 3개")

위젯 시트 바로 아래, 본문 폭으로 복귀하기 전:

- 가로 스크롤 칩 리스트(모바일) / 세로 3줄(데스크톱). 각 칩: 번호(쪽빛 원형, 도면 부호 느낌) + 지시문(15px). 예: `① "안녕하세요"와 "hello"를 넣고 토큰 수를 비교해 보세요`.
- 칩은 정적 텍스트가 기본. 탭 시 해당 조작을 위젯에 프리셋하는 연동은 위젯별 선택 구현(가능하면 권장 — "시키는 대로 눌러보기"의 마찰 제거).

### 5.3 첫 노출 힌트 (1회성)

- 위젯이 뷰포트에 처음 50% 진입 시: 핵심 컨트롤(슬라이더 썸 등)이 1회 왕복 미세 이동(총 900ms) + "만져보세요" 툴팁 1.5초. localStorage로 위젯당 1회 제한. `prefers-reduced-motion`이면 툴팁만.

### 5.4 스켈레톤과 성능

- 스켈레톤: 최종 위젯과 **동일 높이 고정**(meta에 `heightPx` 선언) + 모눈 배경 + 중앙에 위젯 제목 텍스트. 펄스 애니메이션 금지(잔잔한 지면 유지) — 정적 스켈레톤 + 우하단 미세 스피너.
- 조작 반응 예산: 입력→화면 반영 **16ms(60fps)**. 무거운 재계산은 requestAnimationFrame 배칭·디바운스, 그래도 안 되면 Web Worker. 슬라이더가 버벅이는 순간 사이트의 존재 이유가 죽는다 — 성능은 디자인 요구사항이다.
- 터치 타깃 최소 44×44px. 호버 전용 정보 금지(팝오버는 탭 동등 경로 필수).

### 5.5 위젯 내 시각 문법 (전 위젯 공통)

- 토큰 블록: `--tk-*` 순환, `--r-ctl`, 블록 내 텍스트는 대응 fg 색. 탭 시 상세(ID·바이트)는 블록 하단 확장 — 팝오버 남발 금지.
- 확률 막대: `--bar-fill`, 트랙 `--bar-track`, 값 라벨은 막대 끝 tabular-nums. 최댓값 강조는 굵기(600)로 — 색 추가 금지.
- 어텐션: `--attn-hue` 단일색 + 투명도·굵기 이중 인코딩(§2.3). 세기 범례를 위젯 우상단에 상시 표시.
- 상태 판정(VRAM 계산기 등): `--ok/--warn/--err` + 반드시 텍스트 병기("여유 있음/빠듯함/불가").
- 위젯 내부 폰트: UI는 Pretendard, 수치는 mono. 마루 부리는 위젯 내부 사용 금지(도구는 도구답게).

### 5.6 정적 시각 자료 — 다이어그램·표·이미지 (KICKOFF §4.6과 한 쌍)

정적 시각 자료는 "보는 도면", 위젯은 "만지는 도면"이다. 이 구분이 무너지면 위젯의 신호가 죽으므로 아래를 엄수한다.

**다이어그램**
- 구현: 인라인 SVG 컴포넌트, 색은 디자인 토큰만(CSS 변수 → 다크모드 자동). hex 직접 사용 금지 린트 동일 적용.
- 문법: 쪽빛 단색 선(1.5px) + 채움은 `--jjok-100`/`--bg-inset` 2단만. 텍스트 라벨 Pretendard 13~15px. 배경은 페이지 지면 그대로(투명).
- **모눈 금지**: 모눈 패턴은 '만질 수 있음'의 전용 신호(§5.1)다. 정적 그림에 쓰면 신호가 오염된다.
- **폭은 본문 폭(42rem) 유지**: 브레이크아웃(54rem)은 위젯 전용. 폭 차이 자체가 "보는 것 vs 만지는 것"의 구분 장치.
- 캡션 필수: "그림 N. 설명" + 재구성 시 원 출처("Vaswani(2017) Figure 1을 재구성"). 캡션은 `--text-caption`, `--ink-600`.
- 화살표·블록·부호의 표준형은 §9 스타일가이드에 등재 — 등재 없는 신규 부호 사용 금지(다이어그램도 사이트 전체에서 같은 언어를 써야 복습 장치가 된다).

**표**
- 가로 헤어라인만(세로줄·지브라 배경 금지 — 잔잔한 지면 유지). 헤더 15px/600, 상단 2px `--hairline-strong` 룰.
- 수치 열은 tabular-nums 우측 정렬, 단위는 헤더에 1회만.
- 모바일에서 3열 초과 표는 가로 스크롤 컨테이너(레이아웃 파손 금지) + 첫 열 고정.

**이미지(실증 스크린샷)**
- 실제 캡처만(KICKOFF §4.6). 프레임: 1px `--hairline-strong` + `--r-card`, 캡션에 캡처 일자. 과장된 목업 프레임(브라우저 크롬 장식 등) 금지.
- 다크모드에서 라이트 스크린샷은 그대로 두되 테두리로 지면과 분리(반전·필터 금지 — 증거를 가공하지 않는다).

## 6. 페이지 레이아웃

### 6.1 챕터 페이지 (핵심 화면)

```
데스크톱(lg+)                          모바일
┌──────────────────────────┬──────┐   ┌────────────────┐
│ 파트 라벨 ●●○○○           │      │   │ 상단 바(파트·위치)│
│ 챕터 제목 (마루 부리)       │ mini │   │ 제목            │
│ 훅 인용                    │ TOC  │   │ 훅              │
│ 본문 (42rem) ─────────────│(h2)  │   │ 본문            │
│   [====위젯 시트 54rem====]│      │   │ [==위젯 100%==] │
│   해보기 ①②③              │      │   │ 해보기(가로스크롤)│
│ 본문 · Depth 카드          │      │   │ …              │
│ 확인 질문 → 참고문헌 → 배지 │      │   │                │
│ [다음 챕터 훅 카드]         │      │   │ [다음 챕터 카드] │
└──────────────────────────┴──────┘   └────────────────┘
```

- mini TOC: lg 이상에서 우측 고정(h2만, 15px), 현재 섹션 쪽빛 표시. md 이하 미노출(상단 바가 위치 감각 담당).
- 상단 바(모바일): sticky, 파트 라벨 + 파트 내 위치 점 + 읽기 진행 헤어라인(스크롤 연동 1px 쪽빛 라인 — 게이지가 아니라 선).
- 본문 시작 전 요소 순서 고정: 파트 라벨 → 제목 → 훅 → (딸기 스크린샷 같은 도입 Figure) → 본문.

### 6.2 홈 = 커리큘럼 맵 (`/`)

별도 소개 랜딩을 두지 않는다. 홈 자체가 전체 지도이며, 커리큘럼(카드 문구 = 훅 질문)이 곧 최고의 소개다. 섹션 순서(위→아래) 고정:

1. **이어가기 카드** (재방문자 전용 — 진도 localStorage 기반): "이어서 배우기 — [다음 미완 챕터 번호·제목]" + "n/24 챕터" 담백한 텍스트. 히어로보다 위 — 두 번째 방문부터 홈의 임무는 소개가 아니라 복귀다. 첫 방문자에게는 렌더되지 않음.
2. **히어로 = 논지 + 시연**:
   - 첫 문장(마루 부리)은 **사용자 어휘로 앵커링**: "ChatGPT가 하는 일은 단 하나 — 다음에 올 말을 맞히는 것." ('LLM'으로 시작하면 P1 독자가 첫 단어에서 막힌다)
   - 보조 문장에서 용어를 넘겨받는다: "이런 AI를 LLM(대형 언어 모델)이라고 부릅니다. 이 사이트는 그 속을 열어 보여줍니다."
   - 바로 아래 **미니 토크나이저 위젯 임베드**(입력창 "안녕하세요" 프리셋, 즉시 조작 가능) — 설명 대신 시연이 첫인상.
   - 마무리 한 줄: "읽지 말고 만지면서 배우세요" + "1챕터 시작 →" 텍스트 링크. 버튼 그리드·기능 소개 3열 아이콘 금지.
3. **커리큘럼 맵**: 최상단에 일러두기 카드(KICKOFF §7.5 — 1-1 카드 위에 조용히, "건너뛰어도 됩니다" 문구 포함) → 6파트 세로 흐름: 파트 헤더(쪽빛 농도 + 파트명 마루 부리) → 챕터 카드(문구 = 훅 질문, 완독 카드에 인주 스탬프) → 파트 사이 연결 질문(KICKOFF §6 서사 구조)을 가로 헤어라인과 함께 — 맵 자체가 서사를 예고.
4. **지름길 스트립**: 도구 3종(토큰 계산기 · VRAM 계산기 · 양자화 선택기) / 용어사전 / 타임라인 — 담백한 텍스트 링크 카드. (검색 유입자는 홈을 거치지 않고 도구·챕터로 직접 진입한다는 전제는 유지 — 챕터 상단 파트 라벨이 그들의 위치 감각을 담당)
5. **신뢰 스트립**(푸터 위): 인주 도장 아이콘 + "모든 챕터는 원 논문을 근거로 쓰고, 검증일을 표기합니다" + 참고문헌 정책 링크.

금지: 마케팅 랜딩 문법 — 사용자 후기, 뉴스레터 팝업, 통계 숫자 카드, 파트너 로고 스트립.

### 6.3 용어사전 (`/glossary`)

- 상단 검색 + 가나다 색인(sticky). 목록은 2컬럼(md+) 정의 리스트: 용어(600) + oneLiner.
- 상세 페이지: 본문 조판 동일 + "이 용어가 등장하는 챕터" 역링크 목록 + 관련 용어 칩.

### 6.4 도구 페이지 (`/tools/*`)

- 위젯 도면 시트가 주인공(뷰포트 상단 즉시 노출), 그 아래 "원리가 궁금하다면 → 챕터" 카드 + 간단 사용법. 검색 유입 첫 방문자가 3초 안에 도구를 쓸 수 있어야 함 — 서사적 도입 금지.

### 6.5 타임라인 (`/appendix/timeline`)

- 세로 스크롤 단일 페이지. 중앙 수직 쪽빛 라인 + 좌우 교차 사건 카드(연도 mono, 사건명 마루 부리 17px, 요약 2줄, "챕터에서 자세히 →").
- 사건 카드의 연도 표기는 도면 치수선 모티프(가는 헤어라인 + 눈금) — 콘셉트 일관성.

### 6.6 논문 정독 (`/papers/*`)

- 챕터와 동일 조판 + 좌측에 원문 섹션 번호 러닝 헤드. 원문 인용 블록은 인용 규격(§3.3) 재사용.

## 7. 모션 원칙

1. **모든 모션은 질문에 답한다**: "무엇을 가르치는가" 또는 "무슨 상태 변화를 알리는가". 답 못 하면 삭제.
2. 교육 모션(분포가 뾰족해지는 전환, 캐시가 채워지는 과정 등)은 내용이 요구하는 길이를 갖되, **일시정지·단계 이동 가능**해야 한다(스테퍼 병행). 자동 재생 루프는 3회 후 정지.
3. UI 모션은 `--dur-micro`/`--dur-ui` 두 단계만. 페이지 전환 애니메이션 없음(즉시성 = 신뢰).
4. `prefers-reduced-motion`: 교육 모션은 단계 스냅으로 대체(정보 손실 없이), 장식성 잔여 모션은 전부 제거. 도장 스탬프는 즉시 찍힘으로.
5. 스크롤 하이재킹·패럴랙스 금지.

## 8. 접근성 기준 (게이트 4에서 자동+수동 검사)

- 텍스트 대비 4.5:1 이상(caption 포함), UI 요소 3:1 이상 — 토큰 팔레트(§2.3)의 fg/bg 쌍은 이 기준으로 이미 설계됨. 변경 시 재검증.
- 색 단독 정보 전달 금지(어텐션=투명도+굵기, 판정=색+텍스트 — 이미 규격화. 신규 위젯도 준수).
- 전 인터랙션 키보드 경로: 위젯 슬라이더는 방향키(±1)·PgUp/Dn(±10), 스테퍼는 좌우 방향키. 포커스 링(§2.5) 절대 제거 금지.
- 모든 위젯에 시각화 요약 텍스트(`aria` + 화면 표시 겸용 캡션): 예 "현재 설정: 7B 모델, 4비트 → 필요 VRAM 5.2GB, RTX 3080에 여유 있음".
- 이미지 alt 필수(린트), 위젯 도면 시트에 `role="group"` + 라벨.
- 폰트 크기 200% 확대 시 레이아웃 파손 없음(rem 기반 강제).

## 9. 살아있는 스타일가이드 (`/styleguide`)

디자인 일관성은 문서가 아니라 코드로 강제한다. 프로덕션 빌드에도 포함(공개 무방 — 오히려 신뢰 자산).

필수 등재 항목:
1. 토큰 시트: 전 색(라이트/다크 토글, 대비값 자동 표기), 타이포 스케일 실물, 간격 자
2. 컴포넌트 전 상태: §4의 10종 × (기본/호버/포커스/비활성/열림), Term 팝오버, 도장 모션 재생 버튼
3. 위젯 셸: 도면 시트 프레임 + 스켈레톤 + 첫 노출 힌트 데모
4. 콘텐츠 시맨틱: 토큰 6색 순환 예시, 어텐션 세기 범례, 판정 3색, 확률 막대
5. 조판 샘플: 더미 챕터 1페이지 분량(제목~NextHook 전 요소 포함) — **신규 챕터의 시각 기준 원본**

운영 규칙: 새 UI 패턴은 스타일가이드 등재 없이 챕터에 먼저 등장할 수 없다(PR 체크 항목).

## 10. 디자인 QA 체크리스트 (게이트 5 부록 — 재성 수행)

챕터 승인 전 실기기(안드로이드 또는 iOS 1대 이상 + 데스크톱)에서:

- [ ] 위젯을 "만질 수 있어 보이는가" — 스크롤만 하는 제3자 테스트 시 멈추는가
- [ ] 슬라이더·스테퍼 조작이 즉각 반응하는가(버벅임 체감 0)
- [ ] 모바일에서 위젯 전 조작이 엄지로 가능한가(오조작 포함)
- [ ] 다크 모드에서 전 요소 판독 가능한가(특히 토큰 블록·어텐션 선)
- [ ] 위젯 로딩 시 본문이 밀리지 않는가(CLS 체감 0)
- [ ] 훅→위젯→회수의 리듬이 스크롤 리듬과 맞는가(위젯이 너무 늦게/일찍 나오지 않는가)
- [ ] Depth 카드가 눈에 띄되 흐름을 끊지 않는가
- [ ] 참고문헌·검증 배지가 챕터 끝에서 정상 렌더되는가
- [ ] 200% 확대·가로 모드에서 파손 없는가
- [ ] 이 챕터에서 §1.3 금지 목록 위반이 없는가

## 11. 구현 순서와 운영 노트

### 11.1 구현 순서 (KICKOFF Phase에 삽입)

### 11.2 리스킨 가능 구조 (Claude Design 병행 대비)

이 문서의 모든 시각 결정은 §2 토큰을 단일 진입점으로 통과한다. 따라서:
- 다른 비주얼 방향을 실험하고 싶으면 **tokens.css 한 파일 교체**로 사이트 전체가 리스킨된다(콘셉트 §1은 교체 대상, 규격 §3~8은 유지).
- Claude Design 등 외부 도구로 시안을 만들 경우, 산출물을 "토큰 값 제안"으로 번역해 반영한다 — 컴포넌트 코드에 개별 스타일을 심지 않는다.
- 단, §1.3 금지 목록과 §8 접근성 기준은 어떤 리스킨에서도 유지한다(신뢰 톤의 하한선).
